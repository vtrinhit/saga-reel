## 1. stickman-video-director (MIT code; bundled audio per-item CC0/CC-BY; showcase media "redistribution rights not established")

All under `skills/directing-stickman-videos/`: `SKILL.md` router, ~70 `references/*.md` contracts, `scripts/` validators/renderers, `assets/<style>/` packs.

**(a) Engines.** A "Model Engine" = AI video per shot (default Google Flow) from frozen prompt blocks + reference still. B "Autopilot" = narrated, captioned, code-rendered video. No auto-chooser: the user picks a style code (A1–A7 / B1–B7); "ask one short question if ambiguous" (`references/mode-execution-boundaries.md`). B is a declarative manifest (`references/autopilot-runtime.md` §Manifest v1): `shots[{start,end,layers[]}]`, layers `image|pose|text|line|arrow|underline` (B3 adds `path` M/L/Q/C/Z, `rect`, `ellipse`, `group` with `pivotX/pivotY`), animated by `keys[{t,x,y,w,angle,alpha,progress}]` with smoothstep; `from/to` visibility. Each moving layer needs `id` + `motion{role,reason}`; validation fails any >2.5 s window without principal-picture motion (zoom/caption changes don't count): "Images do not gain inferred limb motion automatically." B6 adds a puppet rig (`references/b6-puppet-api.md`, `scripts/b6_puppet.py`): head/body RGBA sprites, arms with sockets/lengths/joint ranges, 5 authored poses `rest/reach/offer/receive/retract`, bounded 2-bone IK for contact hands; reusable actions `offer_track, receive_track, handoff_timeline, reaction_nod, camera_landing` (`scripts/b6_actions.py`).

**(b) Style pack.** `assets/a7/`: `reference-manifest.json`, `approved-prompt-lock.json`, `validated-workflow.json`, `validated-prompts/*.txt`, stills. Manifests are **ad hoc per style** (a6/b3/b7 keys differ). A7 core: `style_id, prompt_lock, style_frames[{file,source_take,source_time_seconds,sha256}], limits[], reference_usage{workflow,primary_drawing_reference,role,submission_evidence[],review_limit}, showcase{sha256,ratio,duration,user_selection}`. Lock file: `approved_at`, `approval_quote` (user's literal words), `approved_rounds`, verbatim `character` + `visual_style` blocks, `hashes{character_sha256,visual_style_sha256}`, `usage: "Repeat both blocks verbatim… Only scene/action/camera vary."` Prompt = `[1 CHARACTER LOCK][2 STYLE LOCK][3 SCENE][4 ACTION / CAMERA]` with timed block 4 ("0-2.5s medium side view: …") (`references/a7-prompt-contract.md`). `validated-workflow.json` logs settings, `prompt_sha256`, `job_id`, user quote, and honest `"not_checked"` fields. B4 lock hash-checked at load (`scripts/b4-style-lock.mjs`), "integrity only".

**(c) Gates.** A (`mode-execution-boundaries.md`): storyboard approval → prompt handoff (a complete stop) → representative test at lowest resolution ("confirms the look, not permission to produce") → production settings incl. **total credit cap including retries** → finished film with no per-shot asks. B has only two approval gates — script/voice confirmation and the ~20 s preview (sound, captions, acting) recorded by `autopilot.mjs approve --note` (hash-bound to sample content) — then `render`; no storyboard gate. Between them a **sound script** is a saved artifact, explicitly not a gate (`references/autopilot-sound-system.md`: per scene an ambience bed; per beat voice plan, background/detail/emotion layers, verbatim text, timecodes "pending" until aligned). Every render emits MP4, SRT/VTT, contact sheet, report. Gate results `pass|fail|not_checked|not_applicable`; `not_checked` blocks acceptance.

**(d) Partial revision.** Shot cache is content-addressed (content, own assets, overlapping captions, fonts, renderer version). "Changing the reviewed sample's content… invalidates approval; adding or revising only later shots does not." A: "Repair only the affected prompt, source range, shot, cut, caption or sound section… recheck… adjacent joins." B6 `plan-iteration` diffs input hashes and lists affected shots + neighbouring cuts. User-confirmed samples become baselines.

**(e) SFX library.** `assets/b-audio-library/catalog.json` (730 SFX + 44 transitions, 31 BGM, 85 stingers), per asset: `id,kind,category,tags[],author,source_url,path,sha256,duration,license{id,url,evidence_paths[],attribution_required,attribution,commercial_use,redistribution},modifications[],qa{peak_dbfs,rms_dbfs},roles[],style_hints[]`; `evidence/<id>/acquisition.json` (download URLs+sha256, `retrieved_at`, archived source page); `CREDITS.md`. Spotting events (`assets/b5/sound-spotting.json`): `time,frame,description,duration,sources[{source_sha256,trim_start,hp_hz,lp_hz}],perspective,sync_tolerance_frames`.

**(f) Publishing kit** (`references/thumbnail-publishing-kit.md`): offered once, only after final approval: 16:9 thumbnail (approved refs, short accurate headline, mobile check), 5 titles (search / curiosity / broad), description + tags (chapters only from verified final timeline), 1 pinned comment = genuine discussion question, checklist (`checked|pending|n/a`, licenses). Saved as `publishing/metadata.md`; a cover edit never re-renders the film.

**(g) Narration drives duration** (`references/autopilot.md` §Voice-led): "Establish narration before timing pictures"; one continuous TTS track; "Never slow speech, insert internal pauses or resynthesize… to fit a visual plan"; shots cover voice + lead/tail with no gaps; `voice.speed` rejected; captions from Whisper word alignment (`scripts/align_captions.py`), one semantic line. In A, storyboard rows keep final time, source duration and retained range separately; N clips ≠ duration/10.

**(h) Styles** (`references/style-catalog.md`): A1 Classic Minimalist light/dark, A2 Beanie (2A Studio Tech / 2B Cinematic), A3 Prehistoric Dark Comedy, A4 Cozy, A5 Historical Cartoon, A6 Amber Noir, A7 Rubber Hose; B1 Minimal Line Art, B2 Colorful Hand-Drawn, B3 Retro TV, B4 Survival Thriller, B5 Character Explainer, B6 Dynamic Meme, B7 Pixel Theater. A style = matrix row (theme, best-for, character design) + verbatim Character DNA + palette contract (≤3 accents, plain words, no hex) + environment spec + negatives + motion rules + caption font/size/placement + voice/audio + approved references + acceptance checks. Storyboard columns (`references/storyboard-template.md`): `Final time | Source dur/retained range | Purpose | Scene | Motion/camera/transition | VO | Translation | BGM/SFX`; each row ends on a "visible interface" the next row inherits.

## 2. Drama platforms

**Toonflow-app (MIT; Bun/TS, Electrobun desktop + web, Drizzle).** Data lives in **canvas JSON files**: `画布/剧本.json` (events, skeleton, episode outlines, scripts), `画布/资产.json` (base + derived assets, prompts, chosen images), `画布/分集/第001集.json` (director plan, storyboard, refs, frames, videos, delivery); nodes in `packages/nodes/*` (text/image/video/audio/imageGeneration/videoGeneration/frameAnalysis/director3d). Pipeline skill `packages/skills/v118workflow/SKILL.md`: 14 steps, each "read confirmed input → do → save → read back → show → wait for confirmation": setup → source/chapter events → story skeleton + episode plan → adaptation strategy → per-episode script → base assets → images → director plan → derived assets → storyboard table/panel/images → video; steps 7–13 loop per episode; video has 3 gates (prompt/config → result → selection). Consistency: `references/deriveAssets.md` — variants hang off a real parent; auto-extract only outfit change/transformation (characters) and time-of-day (scenes), never expressions/poses; 1–5 per parent; each records "difference from base" + "identity to keep". Prompts bind `{{ref N}}` with real global indices and state left/right, facing, eyeline, prop ownership. Storyboard table: `# | description | duration | shot size | camera | dialogue | SFX`. **MCP** (`packages/mcp`): Streamable HTTP `127.0.0.1:10588/mcp` + stdio bridge, bearer token, off by default; instruction "call `getAppState` first… never edit canvas JSON directly". Tools (`apps/server/src/utils/mcp/tools.ts`): fixed `getAppState, searchPluginMarket, installMarketPlugin, listAppOperations, appOperation` (32 ops in `operations.ts`: node/tool/skill install+edit, `listMediaProviders/saveMediaProviderModels` with revision check, asset library, agent sessions); UI tools `openProject, switchPanel, getDocument, openDocument, writeDocument(expectedText), getSettings, updateSettings`; plus every enabled agent/plugin tool (canvas ops, `skillOperator`, ffmpeg, web_search, `developPlugin`, sub-agents/teams) — list is live. Skills exposed as MCP resources; plugin market + scaffolds (`packages/extScaffold`, `nodeScaffold`, `toolScaffold`). Provider routing: `multiTenantModelRouting{configuration json, revision}`.

**huobao-drama (ideas only; Hono + Mastra + Drizzle SQLite).** `backend/src/db/schema.ts`: `dramas, episodes{image_config_id, video_config_id}, characters{appearance, styling, final_prompt, voice_audio_url, reference_images, seed_value}, scenes{location, time, lighting}, props, storyboards{shot_type, angle, movement, result, atmosphere, image_prompt, video_prompt, bgm_prompt, sound_effect, first/last_frame_image, reference_images, status}`, M2M storyboard↔character/prop, `ai_service_configs{service_type, priority, is_default}`, job table `sys_task`. Sheet layout: frontal face close-up + front/side/back full body, white bg, flat light; consistency ranked above beauty. Storyboard: 1 storyboard = 1 video job = 8–15 s segment of 2–4 sub-shots in one scene; duration ≥ dialogue chars ÷ 4.5/s + 2 s. **UI editing**: `routes/skills.ts` GET/PUT `skills/<id>/SKILL[.lang].md` (jailed, language fallback, hot reload); `routes/prompts.ts` per-agent prompt files with `is_default` and code-default fallback; agent tools `save_dedup_characters, save_character_final_prompt, save_storyboards, update_storyboard`.

**BigBanana (ideas only; docs only).** `README_EN.md`: Project → Season → Episode; novel auto-split; "worldview" (maps, locations, music style) injected everywhere. Wardrobe: looks derive from a base look; face stays fixed. Shots auto-attach scene image + wardrobe + prop refs. **Plan pre-review** before batch (per shot: nine-grid board or start/end keyframes); batch gap-fill missing assets; central prompt manager with version rollback; export clips for Premiere/Resolve.

**aid-studio (MIT; Spring + MySQL + Quartz; `sql/aid-init.sql`).** `aid_role_prop_scene{asset_type, name_normalized, aliases_name, age_range, role_level, profile_data, expected_appearances, available_slots, has_crowd}` → `_form{name "everyday/battle-damaged", change_reason, prompt_text}` → `_form_image{prompt_snapshot, reference_images, batch_no, is_use}`. `aid_scene_plot{plot_summary, character_actions, character_states, key_dialogues, scene_function, time_of_day, era_coordinate, date_coordinate, weather}`. `aid_storyboard_shot_group_plan{display_code, plot_content, characters_json, split_reason, previous_summary, next_summary}`. `aid_storyboard{script_params, image_prompt, video_prompt, final_image_id, final_video_id, final_audio_id}` + takes `aid_gen_record{first/last_image_id, is_selected}`. Jobs `aid_media_task{provider_route_snapshot_json, request_hash, idempotency_key, provider_task_id, status, retry_count}`. Agents are rows `aid_agent{agent_code, prompt_content, model_code}` (25, e.g. `aid_casting_director, aid_storyboard_writer, aid_visual_director_multiref`); per-project routing `aid_project_gen_config{scene_code, agent_code, model_code, resolution}`; voices `aid_role_voice_binding`; snippet library `aid_prompt_lib{prompt_type, content, content_en, cover_url}`.

**novanova-studio (MIT; Spring + Postgres, Next.js canvas; `server/.../db/migration/`).** `V33`: `comic_drama_shots{shot_size, composition, visual_description, action_description, camera_movement, lighting_atmosphere, dialogue_voiceover, sound_description, style_override, revision}`, `asset_versions{variant_type, appearance_description, reference_media[]}`, `shot_asset_versions{reference_role}`, `prompt_versions`, **`change_impacts{source→target, change_summary, status}`**. `V41` **Story Bible**: `items{type character|location|relationship|event|storyline, status pending|confirmed|rejected, locked, story_time, story_order}`, `aliases`, `links{role}`, **`evidences{document, start/end offset, quote}`**; staged resumable analysis jobs (segment → chapter → book). Per-model `request_concurrency` (`V10`); skills table + market (`V20`, `V92`).

**Kinema (ideas only; Python engine + CLI, `AGENTS.md`).** Agent layer writes structured PromptSpec/ChapterPlan; deterministic engine (no LLM) compiles prompts, writes files, versions, lineage; providers in `config/models.yaml`. One `style_prompt` per project, never repeated per shot. Edits: `context → validate → apply(expected_revision)`. Lineage by content fingerprint: changed dialogue stales voice+clip, new frame stales clip. Review states `wfa / done (locked) / retake / omt` (shots never deleted). Gates: first shot + most-different shot test, then all images; `gen-video --dry-run` shows per-shot prompt + price. Voice described in 6 slots, no emotion words.

## 3. Skill repos

**drama-skills (MIT).** Skills: `short-drama` (router), `-novel-analyze, -develop, -breakdown, -write, -assets, -image-prompts, -storyboard, -video-prompts, -produce, -edit, -review`; one markdown file per stage per episode; every rule has an ID (`IMG-03`, `CON-07`, `VID-08`) and class (`craft_default` / `reviewed_invariant` / `structural_invariant`).
- Sheet prompt order (`short-drama-image-prompts/references/sheet-prompt-guide.md`): sheet type + subject → fixed core look → this outfit/view/state → layout + scale ref → material/colour/soft front-side light → background + exclusions. Fragment: "…front view alongside a head-and-shoulders profile inset on one shared ground line… plain neutral light-grey background, consistent facial identity and hair length across both views, no view labels, no callout lines, no dimension marks, no text, no watermark."
- **Continuity lock** (`short-drama-assets/references/continuity-and-locks.md`): `LOCK-ID «name» (shots: in-frame) · lock word: pine-green lapel service jacket` — static "colour + material/cut + object" phrase that must appear verbatim in sheet, first-frame and any video prompt lacking a reference that already locks it; negated mentions don't count; validated.
- Shot (`short-drama-storyboard/SKILL.md`): bound setting entries, refs `REF-…` (real file) / `PLAN-…` (pending), each with one role of 10: appearance, subject, outfit-state, spatial-layout, composition, scale, effect, start-frame, end-frame, style. Stable IDs: insertions get new IDs, retired IDs never reused.
- Video prompt (`…/video-prompt-guide.md`): image-to-video does not re-describe what the reference carries — only start state (weight, gaze, hands); then present-tense causal action chain, emotion as visible behaviour, camera path/lens, timed segments.
- Review (`short-drama-review/references/generated-media.md`): per take keep / trim / post-fix / regenerate-waivable (major) / must-regenerate (blocker) / re-cut; verdicts `PASS|PROVISIONAL|REVISE|REJECT`; blame reference vs generation; after 1–2 identical failures stop rerolling; offer keep-and-hide / move info / drop.

**shuohao-skills (Apache-2.0).** README order: `novel-outline` → `novel-characters` (profile, look + voice prompt) → `character-refs` → `novel-art` → `novel-script` (alternating action beats and lines with speaker + tone; duration from speech rate) → `novel-staging` (opening blocking from the scene image) → `novel-storyboard` (segment ≤15 s → cuts 2–5 s → keyframes). Novel→outline method (`novel-outline/references/outline-pass.md`): cut subplots (1 main + ≤1 sub, each cut with a reason) → merge functionally duplicate characters, tier them (lead 1–5, support ≤10) → cap main locations (4 + ⌈episodes/10⌉, 5–15) → place major payoffs (gap ≤3 episodes) then minor → list narrative props (≤8; "would the plot collapse if it broke?"); key keeps cite verbatim source evidence; 14 script-checked gates; each emits JSON + MD + HTML report. Cut JSON (`novel-storyboard/examples/渡口-storyboard.json`): `{beats[], seconds, size, camera, characters[C01], props[P01], frame, shot, lens, cameraPosition, composition, eyeline, focus, stability}`. Ref method (`character-refs/references/prompting.md`): text-only front full-body anchor 2:3 with geometric frontality ("shoulders, hips and feet square to camera, nose on the face midline"); derive head-shot 4:5 ("Zoom in to an extreme close-up head-and-shoulders portrait, passport-photo framing"), side, back ("Rotate the camera 180 degrees around her"), detail 1:1 — each referencing **only the anchor**, never chained; edit models obey the first sentence; short consistency line ("Keep her exactly the same person as in the reference image: face, hairstyle, top, bottom"); no stitched multi-view sheets as inputs (caused extra people).

**awesome-short-drama-skills (CC0).** Curated index + `short-drama-skill-finder`; `data/taxonomy.toml` stages, `packs.toml` (long serials → memory files + consistency checks, `mengxiujie/ManjuForge`). Pointer list only.

## 4. ViMax / MovieAgent / VideoClaw

**ViMax (MIT).** Agents `agents/*.py`: novel_compressor, event_extractor, scene_extractor, global_information_planner, character_extractor, character_portraits_generator, screenwriter, storyboard_artist, camera_image_generator, reference_image_selector, best_image_selector. JSON (`interfaces/`): `Event{description, process_chain[]}`, `Scene{environment, characters[{identifier, is_visible, static_features, dynamic_features}], script}`, `CharacterInNovel{identifier, active_events, static_features}`, `ShotDescription{cam_idx, visual_desc, variation_type, ff_desc, lf_desc, motion_desc, audio_desc}`, `Camera{active_shot_idxs, parent_cam_idx, is_parent_fully_covers_child, missing_info}`. Long-form (`pipelines/novel2movie_pipeline.py`): events → per-event RAG (embed + rerank top-10) → scenes extracted sequentially with prior scenes → characters merged per event then into a novel registry → base portrait per character → per-scene portrait = base + dynamic features. Ref selection: ≤8 refs + text mapping elements to images; one view per character by facing; prefer same-camera, newest frames; drop redundant refs.

**MovieAgent (ideas only).** `movie_agent/system_prompts.py`: screenwriter → script supervisor (yes/no loop) → scene planning → shot creation; shot JSON `{Involving Characters{name: bbox}, Plot/Visual Description, Emotional Enhancement, Shot Type, Camera Movement, Subtitles{name: line}}` — boxes drive regional character control.

**VideoClaw (MIT).** `video-claw/SKILL.md`: 7 stop points (story/visual, model config, script, character/scene images, storyboard list with per-episode/total duration, reference images, clips); protocol fetch → show → ask → wait → execute, each with a web URL. `FilmAgent/`: director/screenwriter/actor/cinematographer role prompts; discussion cut impossible actions.

## 5. Apply to SagaReel (ranked)

1. **Story Bible with evidence.** `bible_item{type, summary, attributes, status pending|confirmed|rejected, locked, story_time, story_order}`, aliases, links, `evidence{episode, start, end, quote}` (novanova) + per-scene state `{time_of_day, era, date, weather, character_states}` (aid). Per-episode context by retrieval (ViMax), never the whole book.
2. **Character → Look → RefSet.** `look{diff_from_base, keep_features, lock_word, prompt}`; RefSet via shuohao method (anchor + anchor-only derived views); voice binding per character.
3. **Reference slot builder for the 9-ref API**: `{asset_version_id, role}` with drama-skills' 10 roles, ViMax selection rules, prompts naming what each `{{ref N}}` provides (Toonflow).
4. **Clip fields**: stable never-reused `code`, `scene_id`, `beats`, `final_start/end`, `source_duration`, `trim_in/out`, `shot_size`, `angle`, `camera_move`, `lens`, `composition`, `eyeline`, `characters[{id, look_id, position, facing}]`, `props`, `first_frame_desc`, `last_frame_desc`, `motion_desc`, `dialogue[{speaker, text, mode}]`, `sfx_desc`, `refs[]`, `status`, `review_state`, `takes[]`, `prompt_versions[]`; duration floor from dialogue length.
5. **Style pack files** `styles/<id>/style.json` (DNA, style block, palette, negatives, motion, captions, audio, refs with sha256, limits) + `lock.json` (approval quote, blocks, hashes) + `validated/*.txt` (stickman A7); prompt = locked blocks verbatim + scene + timed action.
6. **Agents submit specs, engine compiles prompts** from editable templates; edits via `plan → validate → apply(expected_revision)` (Kinema, ideas only — implement independently).
7. **Lineage & partial redo**: fingerprints + field→stage invalidation (Kinema idea) + `change_impacts` rows (novanova); approved = locked; content-addressed clip cache (stickman).
8. **Episode gates** (our design; audio plan made a gate deliberately): script → assets → storyboard → 2-shot test (Kinema idea) → frames → audio plan → ~20 s preview with sound (stickman) → full render → publish kit; approval quote + hash; credit cap incl. retries; priced dry-run.
9. **Job table** with idempotency key, request hash, route snapshot, provider task id, retries, cost; per-model concurrency; check provider before resubmitting.
10. **Editable prompts/skills as data**: agents table + SKILL.md folders, language fallback, version rollback. Ship MIT/Apache-derived defaults: Toonflow `[Visual][Motion][Camera][Audio][Narrative]` and `[References][Instruction]`, drama-skills sheet order, shuohao view sentences, stickman 4-block prompt.
11. **Review triage** taxonomy + verdicts + `not_checked` honesty; stop rerolling after 2 identical failures.
12. **Narration-led montage engine**: TTS → alignment → shots fit speech; semantic one-line captions; ≤2.5 s static; layered keyframe manifest with `motion.reason`.
13. **Audio library** using stickman's catalog/licence schema, auto credits, per-beat sound script.
14. **MCP**: `get_app_state` first, live tool list, skills as resources, no raw-JSON writes (Toonflow); stop-point protocol (VideoClaw).
15. **Publishing kit** per episode; cover edits never re-render.
