## 1. stickman-video-director (MIT code; bundled audio per-item CC0/CC-BY; showcase media rights explicitly "not established")

Root of everything: `skills/directing-stickman-videos/` (abbrev. `S/`). One `SKILL.md` router + ~70 `references/*.md` style/gate contracts + `scripts/` validators/renderers + `assets/<style>/` packs.

**(a) Engine A vs B.** A "Model Engine" = AI video per shot (Google Flow/Omni Flash by default) driven by frozen prompt blocks + reference image; B "Autopilot" = narrated, captioned, code-rendered video from layered stills. No automatic chooser: routing is by the **style code the user picks** (A1–A7 vs B1–B7), with "ask one short question if ambiguous" (`references/mode-execution-boundaries.md`). B is a declarative manifest (`references/autopilot-runtime.md` "Manifest v1"): `shots[{start,end,layers[]}]`, layer types `image|pose|text|line|arrow|underline` (B3 adds `path` with M/L/Q/C/Z commands, `rect`, `ellipse`, `group` with `pivotX/pivotY`), each animated by `keys:[{t,x,y,w,angle,alpha,progress}]` interpolated with smoothstep; `from/to` for visibility. Every moving layer needs `id` + `motion:{role,reason}`; validator fails any >2.5 s window without "principal-picture motion" (camera zoom/caption changes don't count). "Images do not gain inferred limb motion automatically" — motion must be authored as separate layers/pose sprites. B6 goes further: `scripts/b6_puppet.py` + `references/b6-puppet-api.md` — character package `package.json` (schema `b6-puppet/1`) with separate head/body RGBA sprites (sha256 + 3×3 `image_to_local` matrix), arms with `socket`, `lengths`, `pole`, joint ranges, five authored poses `rest/reach/offer/receive/retract`, bounded 2-bone IK only for contact hands, head nod ≤±20°. Reusable actions in `scripts/b6_actions.py`: `offer_track`, `receive_track`, `handoff_timeline`, `reaction_nod`, `camera_landing`. Layers JSON example: `assets/b6/hong-kong-v90/source/work/*/assets/layers.json`.

**(b) Style pack layout.** `assets/a7/`: `reference-manifest.json`, `approved-prompt-lock.json`, `validated-workflow.json`, `validated-prompts/*.txt`, reference stills. **Manifest schema is ad hoc per style** (a6 keys `schema,scope,assets`; b3 `schema,style,version,status,authority_order,references,motion,production_rules…`; b7 ~25 keys) — no single schema. A7 core: `style_id`, `name_*`, `prompt_lock` (file), `style_frames[{file,source_take,source_time_seconds,sha256}]`, `limits[]`, `reference_usage{workflow,primary_drawing_reference,role,submission_evidence[],review_limit}`, `showcase{…sha256,ratio,duration,user_selection,existing_review}`. **Lock** (`approved-prompt-lock.json`): `version`, `approved_at`, `approval_quote` (user's literal words), `approved_rounds`, verbatim `character` and `visual_style` blocks, `hashes.{character_sha256,visual_style_sha256}`, `usage: "Repeat both blocks verbatim… Only scene/action/camera vary."` Prompts = 4 blocks `[1 CHARACTER LOCK][2 STYLE LOCK][3 SCENE][4 ACTION / CAMERA]` (`references/a7-prompt-contract.md`), block 4 timed (`0-2.5s medium side view: …`). `validated-workflow.json` records `observed_settings{provider,model,resolution,seconds,ratio}`, accepted examples with `prompt_sha256`, `job_id`, `user_quote`, and honest `full_assistant_playback:"not_checked"`. B4 lock is enforced at project load by `scripts/b4-style-lock.mjs` (schema `b4-style-lock-v3`, hash check of resources) — integrity only, "cannot evaluate a generated picture's aesthetics".

**(c) Gates.** A chain (`mode-execution-boundaries.md` table): 1 Storyboard (approved table) → 2 Prompt handoff (complete stopping point) → 3 Representative test at lowest resolution (look only, not production permission) → 4 Production settings (final res + **total credit cap incl. retries**) → 5 Finished film (no per-shot asks). B chain: script/outline+voice → **sound script** (`references/autopilot-sound-system.md`: per scene "environment bed" + per sentence/beat: voice plan, background layer, detail layer, emotion layer, verbatim text; timecodes "pending" until voice aligned) → `validate` → `preview` (~20 s "or the complete natural opening", with sound, captions, acting) → user approval recorded via `autopilot.mjs approve --note` (approval hash-bound to sample content) → `render`. Each stage writes MP4+SRT/VTT+contact sheet+verification report. Review gates recorded `pass|fail|not_checked|not_applicable`; `not_checked` blocks "accepted". No separate storyboard-image gate in B.

**(d) Partial revision.** Shots are cached content-addressed (content, own assets, overlapping captions, fonts, renderer version). "Changing the reviewed sample's content… invalidates approval; adding or revising only later shots does not." A: "Repair only the affected prompt, source range, shot, cut, caption or sound section… recheck the repair and adjacent joins." B6 `plan-iteration` diffs input SHA inventory and recommends affected shots + neighbouring cut frames; shots may declare `asset_inputs[]` to scope this. User-confirmed samples become baselines never re-reviewed.

**(e) SFX library.** `assets/b-audio-library/catalog.json` (774 SFX/transitions, 31 BGM, 85 stingers): per asset `id,title,kind,category,tags[] (EN+ZH),author,source_id,source_url,path,sha256,original_sha256,canonical_pcm_sha256,duration,sample_rate,channels,license{id,url,evidence_paths[],attribution_required,attribution,commercial_use,redistribution,modifications_allowed},modifications[],qa{decode,peak_dbfs,rms_dbfs},roles[],style_hints[]`. Per source `evidence/<id>/acquisition.json` (download URLs + sha256, `retrieved_at`, license declaration, archived `source.html.txt`); `CREDITS.md` with copy-ready attribution. Sound events (`assets/b5/sound-spotting.json`): `time,frame,description,duration,peak_dbfs,sources[{source_sha256,trim_start,hp_hz,lp_hz}],perspective,sync_tolerance_frames`.

**(f) Publishing kit** (`references/thumbnail-publishing-kit.md`): offered once only after final-video approval; 5 items: 16:9 thumbnail (reuse approved refs, short accurate headline, mobile-readability check), **5 titles** (search intent / curiosity / broad), description+tags (chapters only from verified final timeline), **1 pinned comment** = genuine discussion question, pre-publish checklist (each item `checked|pending|n/a`, licenses). Saved to `publishing/metadata.md`; checkpoint key `publishing_kit`; a cover revision never re-renders the film.

**(g) Narration drives duration** (`references/autopilot.md` "Voice-led production"): "Establish narration before timing pictures"; one continuous TTS track; "Never slow speech, insert internal pauses or resynthesize… to fit a visual plan"; shots must cover voice length + `lead`/`tail` with no gaps; `voice.speed` is rejected; captions from word alignment (`scripts/align_captions.py`, Whisper), semantic single-line groups. Shots ~2–4 s, max 2.5 s without picture change (B4: hard 3 s). In A, clip count N ≠ duration/10; storyboard rows hold final-time, source duration and retained range separately.

**(h) Styles** (`references/style-catalog.md`, `SKILL.md`): A1 Classic Minimalist light/dark, A2 Beanie 2A Studio Tech / 2B Cinematic Story, A3 Prehistoric Dark Comedy, A4 Cozy Storytelling, A5 Historical Cartoon, A6 Amber Noir, A7 Rubber Hose; B1 Minimal Line Art, B2 Colorful Hand-Drawn, B3 Retro TV, B4 Survival Thriller, B5 Character Explainer, B6 Dynamic Meme, B7 Pixel Theater. A style definition = matrix row (theme, best-for, character design) + verbatim **Character DNA** anchor + **palette contract** (≤3 accent colours, plain words, no hex) + environment spec + **negative constraints** + motion dynamics + audio continuity + caption font/size/placement + approved reference media + acceptance checklist. Storyboard header (`references/storyboard-template.md`): title, hook, ratio/duration/style, voice profile, palette meanings, sound plan, per-clip timing + reference roles; table columns `Final time | Source/generated duration/retained range | Narrative purpose | Scene | Motion/camera/transition | VO | Translation | BGM/SFX`; every row ends with a "visible interface" the next row inherits (continuity).

## 3. Skill repos

**drama-skills (MIT)** — 12 skills under `skills/`: `short-drama` (router), `-novel-analyze`, `-develop`, `-breakdown` (reverse-engineer benchmark dramas), `-write`, `-assets`, `-image-prompts`, `-storyboard`, `-video-prompts`, `-produce` (adapter contract, preview before paid run), `-edit` (Remotion cut list `剪辑单.md`), `-review`. One markdown artifact per stage per episode: `剧集/<EP>/剧本.md → 视觉设定.md → 图片提示词.md → 分镜.md → 视频提示词.md → 剪辑单.md`; every rule has an ID (`IMG-03`, `CON-07`, `SHT-17`, `VID-08`, `REV-15`) and a class (`craft_default` / `reviewed_invariant` / `structural_invariant`) so reviews cite rules.
- Sheet prompt order (`short-drama-image-prompts/references/sheet-prompt-guide.md`): (1) sheet type + subject, (2) fixed core look (bone structure, not "8K masterpiece"), (3) this outfit/view/state, (4) layout + size reference ("shared ground line… no view labels, no callout lines, no dimension marks"), (5) material/colour/light (soft front-side key; no under-light), (6) background + exclusions. Example: "Full-body character sheet of a tall, lean woman around thirty, front view alongside a head-and-shoulders profile inset on one shared ground line… plain neutral light-grey background, consistent facial identity and hair length across both views, no view labels, no callout lines, no dimension marks, no text, no watermark."
- **Continuity lock** (`short-drama-assets/references/continuity-and-locks.md`): `连戏锁: LOCK-JIANGCHEN-DRESS《name》(shots: in-frame; image item: IMG-…) · lock word: pine-green lapel service jacket`. Lock word = short static noun phrase "colour + material/cut + object", must appear verbatim in sheet prompts, first-frame prompts and any video prompt **not** already carrying a reference image that locks that look; negated occurrences ("no …") don't count; a validator checks it.
- Storyboard shot (`short-drama-storyboard/SKILL.md`): `出场设定` (bound setting entries: person/outfit/location/prop + control scope), `图片提示词项`, `输入参考图` with `REF-…`(real file)/`PLAN-…`(to be attached) and exactly one **reference role** from 10: appearance, subject, outfit-state, spatial-layout, composition, scale, effect, start-frame, end-frame, style. Stable IDs: tweak keeps `SHOT-…`; inserted shot gets new ID (no renumbering); merged/rebuilt shots retire IDs forever.
- Video prompt (`short-drama-video-prompts/references/video-prompt-guide.md`): (1) opening pose + reference split — image-to-video does NOT re-describe face/outfit/room carried by the reference, only starting state (weight, gaze, hands, distance to target); (2) causal action chain in present tense; (3) emotion → visible gaze/breath/body; (4) camera path + optional focal length (24/35/50/85 mm) + timed segments; (5) local deformation notes.
- Review (`short-drama-review/references/generated-media.md`): 6-way triage per take — keep (note) / trim around defect (minor) / post-fix (minor) / suggest regenerate, creator may waive (major) / must regenerate (blocker: missing key action/line, face swap, reversed axis) / re-cut (final only). Verdicts `PASS | PROVISIONAL | REVISE | REJECT`; re-review only reworked clips. Attribution: bad reference image vs bad generation; after 1–2 identical failures stop rerolling → rewrite or split shot; persistent failure → offer user 3 exits (keep & hide in edit / move info to neighbour shot / drop shot).

Derived views reference **only the anchor** (never chain → drift): head-shot 4:5 "Zoom in to an extreme close-up head-and-shoulders portrait, passport-photo framing" (framing first, restated at end); side "Full-body side profile… facing the right edge, not looking at camera"; back "Rotate the camera 180 degrees around her" + back-only details; detail 1:1 "Zoom in to an extreme close-up of only <part>". Edit models obey mainly the **first sentence**. Consistency line short: "Keep her exactly the same person as in the reference image: face, hairstyle, top, bottom" — head-shot lists only face/hair/top. **Never use stitched multi-view sheets as references**; multi-character shots worked 4/4 only with "heroine head-shot + anchor, hero anchor".

## 4. ViMax / MovieAgent / VideoClaw

**ViMax (MIT; Python, LangChain)** — agents `agents/{novel_compressor, event_extractor, scene_extractor, global_information_planner, character_extractor, character_portraits_generator, screenwriter, script_planner, script_enhancer, storyboard_artist, camera_image_generator, reference_image_selector, best_image_selector}.py`; pipelines idea2video / script2video / novel2movie.
- JSON (`interfaces/`): `Event{index, description, process_chain[]}`; `Scene{idx, environment, characters[CharacterInScene{identifier_in_scene, is_visible, static_features, dynamic_features}], script}`; `CharacterInEvent{identifier_in_event, active_scenes{scene→id}, static_features}`; `CharacterInNovel{identifier_in_novel, active_events, static_features}`; `ShotDescription{idx, cam_idx, visual_desc, variation_type large|medium|small, variation_reason, ff_desc, ff_vis_char_idxs, lf_desc, lf_vis_char_idxs, motion_desc, audio_desc}`; `Camera{idx, active_shot_idxs, parent_cam_idx, parent_shot_idx, is_parent_fully_covers_child, missing_info}` (camera tree: child frames derived from parent camera's frame).
- Long-form memory (`pipelines/novel2movie_pipeline.py`): compress novel → events → per-event RAG (embeddings + rerank top-10 chunks per process step) → scenes extracted sequentially with previous scenes as context → merge characters within event, then into novel registry (`modified_features`) → one base portrait per novel character → per-scene portrait = base portrait + scene dynamic features (outfit/injury).
- Reference selection (`agents/reference_image_selector.py`): inputs frame description + indexed descriptions of all portraits and prior frames; output `{ref_image_indices ≤8, text_prompt}` where the prompt says which element follows which image ("The man should reference Image 0. The landscape should reference Image 1."). Rules: prefer same-camera prior frames, newer frames over older, drop redundant refs, only one view per character (pick front/side/back by facing), new character → portrait first.

**MovieAgent (no LICENSE → ideas only)** — `movie_agent/system_prompts.py`: chain screenwriter(CoT) → script supervisor (`Feedback: yes|no` loop) → ScenePlanning → ShotPlotCreate. Sub-script JSON `{Plot, Involving Characters[], Timeline, Relationships{"A - B": …}, Reason for Division}`; shot JSON `{Involving Characters{name: [x1,y1,x2,y2]}, Plot/Visual Description, Emotional Enhancement, Shot Type, Camera Movement, Subtitles{character: line}}` — per-character **bounding boxes** feed regional control (ROICtrl/StoryDiffusion) with per-character photos + voice clones.

**VideoClaw (MIT)** — `video-claw/SKILL.md`: agent skill driving a local web service with **7 hard stop points**: 0 story & visual confirmation, 1 model/parameter config, 2 full script, 3 character/scene images, 4 storyboard list (shot count, per-episode and total duration), 5 reference images, 6 video clips; post-production needs no stop. Stop-point protocol: fetch artifact → show → ask → wait → execute; each stage sends a web URL. `FilmAgent/` = role-play multi-agent film planning (director, screenwriter, actor, cinematographer prompts in `FilmAgent/Prompt/`); finding: director–screenwriter discussion reduces impossible actions, actor–director discussion aligns dialogue to profiles.
